Исправлено: корректный префикс в JAR и `pack_format` **48** в `data/minecraft/datapacks/ratlantis/pack.mcmeta` (для MC 1.21.1).

**Исправление приручения диких крыс (2026-05-23):** прогресс шёл только при `CHEESE_ITEMS` и `ItemEntity.getOwner()`; в 1.21.1 бросивший хранится в `thrower`, а не в owner. Добавлены `RatUtils.isCheeseItem`, `resolveCheeseFeedingPlayer`, прогресс при съедании сыра (`Rat.onItemEaten`), кормление с руки (`mobInteract`), цель поиска еды перенесена в `goalSelector`. Порог приручения: **5** кусков сыра (было 15) или **50** доверия с шансом **50%** (было 100 и 33%). Повторное исправление: проверка сыра теперь делается по копии `ItemStack` до уменьшения количества, потому что после `shrink(1)` один кусок становился пустым предметом и прогресс не начислялся; если у выброшенного сыра нет владельца, кормящий определяется по ближайшему игроку.

**Исправление падения при фактическом создании мира (2026-05-23):** `PlagueDoctorWorldData.get` вызывал `level.getServer().getLevel(dimension)` во время `ModifyCustomSpawnersEvent` / конструирования `ServerLevel` — уровень ещё не зарегистрирован, `dataLevel == null`, NPE в `getDataStorage()`. Исправлено: хранение через переданный `ServerLevel.getDataStorage()`; в `PlagueDoctorSpawner` — запасные значения при недоступных данных.

**Исправление интерфейса крысы и крашей после приручения (2026-05-23):**

- **GUI по ПКМ:** в `ModClientEvents.registerMenuScreens` не был зарегистрирован экран `rats:rat_container` — в логе `Failed to create screen for menu type: rats:rat_container`. Добавлена регистрация `RatScreen` с чтением id крысы из extra-данных `openMenu` (как в `InventoryRat.openGUI`).
- **Отключение при клике:** пакет `rats:sync_arm_swing` отправлял пустой `ItemStack` при любом левом клике в воздухе; в 1.21.1 сеть запрещает пустые стеки (`Empty ItemStack not allowed`). Пакет уходит только если предмет в руке не пустой.
- **Рендер пирата / шляп:** `RatHelmetLayer.getArmorResource` вызывал `BuiltInRegistries.ARMOR_MATERIAL.getKey(...).getPath()` для материалов шляп (`Holder.direct`, вне реестра) — NPE. Текстура берётся из `ArmorMaterial.Layer.texture()`.
- **Сохранение крысы:** в NBT писался пустой `FluidStack` (`transportingFluid` по умолчанию `EMPTY`, проверка была `!= null`). Сохранение только при `!transportingFluid.isEmpty()`.

**Поведение ПКМ (не баг):** интерфейс открывается у **приручённой** крысы **владельца**, **без Shift**, **без посоха** в любой руке; с **сыром в руке** срабатывает кормление, а не меню.

## Основные группы оставшихся ошибок

### Capabilities

Статус: основной слой переписан.

Старые классы, которые были основным блокером:

- `LazyOptional`
- `Capability<T>`
- `ForgeCapabilities`
- `getCapability(...)` на сущностях и block entity

В NeoForge 1.21.1 эта система переработана:

- `LazyOptional` удалён;
- запросы возвращают `null` вместо optional-обёртки;
- используются `Capabilities.ItemHandler.*`, `Capabilities.FluidHandler.*`, `Capabilities.EnergyStorage.*`;
- block capability лучше запрашивать через `level.getCapability(...)`;
- регистрацию provider нужно делать через `RegisterCapabilitiesEvent`.

Затронутые места:

- `InventoryRat`
- `TamedRat`
- `RatDepositGoal`
- `RatPickupGoal`
- `AutoCurdlerBlockEntity`
- `RatCraftingTableBlockEntity`
- `RatCageWheelBlockEntity`
- `UpgradeCombinerBlockEntity`
- `RatQuarryBlockEntity`
- другие машины и цели.

Дальше нужно проверить поведение в игре после восстановления сетевого слоя.

### Registries

Старые классы:

- `ForgeRegistries`
- `RegistryObject`

В NeoForge 1.21.1 реестры используют:

- `BuiltInRegistries` для ванильных реестров;
- `NeoForgeRegistries` для реестров NeoForge;
- `DeferredHolder` / специализированные `DeferredItem`, `DeferredBlock` вместо старого `RegistryObject`.

Статус: первый проход сделан. Остались ручные места, где реестр используется не для регистрации, а для чтения данных, тегов или custom registry.

### Client overlay / events

Ошибки:

- `VanillaGuiOverlay` больше нет в старом пакете;
- `RenderGuiOverlayEvent` изменён;
- часть client events переименована;
- `LivingEvent.LivingTickEvent` больше не совпадает с текущим API.

Затронуты:

- `ForgeClientEvents`
- `ModClientEvents`

Часть client overlay уже переведена на `RenderGuiLayerEvent` и `VanillaGuiLayers.PLAYER_HEALTH`.

### Minecraft API

Ошибки:

- `MobType` удалён или заменён другой системой;
- `RecipeBookMenu` теперь требует два generic-параметра;
- `RecipeHolder` переехал или заменён;
- часть рецептов/меню нужно обновлять под 1.21.1.

Затронуты:

- `TamedRat`
- `PiedPiper`
- `RatCraftingTableMenu`
- `RatCraftingTableBlockEntity`

### Сеть

Старый сетевой слой:

- `SimpleChannel`
- `NetworkRegistry`
- `NetworkEvent.Context`
- `registerMessage(...)`

В NeoForge 1.21.1 требуется новый слой:

- `CustomPacketPayload`;
- `StreamCodec`;
- `RegisterPayloadHandlersEvent`;
- `PayloadRegistrar`;
- отправка через `PacketDistributor.sendToServer`, `sendToPlayer`, `sendToAllPlayers` и другие прямые методы.

Это один из главных оставшихся блокеров запуска полноценного gameplay-теста.

## Следующий технический шаг

Самый правильный порядок:

3. Полностью переписать сеть на `CustomPacketPayload`, без временного совместимого слоя.

5. Последним этапом чинить client overlay и JEI API.

## Важное замечание

Порт с 1.20.1 на 1.21.1 оказался не простой заменой версий. Между этими версиями NeoForge изменил базовые системы, от которых Rats сильно зависит:

- capabilities;
- registries;
- сетевые пакеты;
- клиентские события;
- меню и рецепты.

Поэтому текущий этап — это уже не «обновить Gradle», а полноценная миграция архитектурных слоёв.
