# План разработки Rats Reborn

> **2026-05-23:** порт API на Minecraft 1.21.1 / NeoForge 21.1.228 закрыт (сборка, JAR, миксины, загрузка клиента). Ниже — улучшения геймплея и инфраструктуры **после** порта; см. [`12-статус-порта-1.21.1.md`](12-статус-порта-1.21.1.md). **Краткий план ближайших спринтов** — [`15-план-доработок.md`](15-план-доработок.md).

Этот план составлен после проверки исходников `Rats-1.20` и фиксирует, какие механики нужно менять, где они находятся в коде и в каком порядке безопаснее идти.

## Главная цель

Сделать Rats Reborn не просто портом на Minecraft 1.21.1, а более надёжной версией мода:

- меньше рутины в базовых действиях;
- понятные правила работы крыс;
- нормальный поиск пути;
- совместимость с Create, Farmer's Delight и похожими техническими модами;
- явные ошибки и подробное логирование вместо молчаливых отказов;
- документация после каждой правки.

## Что уже подтвердилось по коду

| Проблема | Где сейчас | Что не так |
|----------|------------|------------|
| Приручение 10-15 сыров | `WildRatTargetFoodGoal` | Порог `cheeseFeedings >= 15`, доверие `wildTrust >= 100` |
| Трубы не работают как проход | `RatTubeBlockEntity`, `RatTubeMoveControl`, `RatNodeEvaluator` | Старый A* закомментирован, движения по сети нет |
| Задачи transport могут ломаться после перезахода | `TamedRat` | `DepositFacing` и `PickupFacing` читаются из NBT, но не сохраняются |
| Радиус непонятен | `InventoryRat.getRadius()` | Пользовательский радиус работает только если задан центр |
| Конфликты улучшений устарели | `RatsUpgradeConflictRegistry` | Класс помечен `@Deprecated`, сам автор оставил TODO |
| Ускоритель / манипулятор времени | `RatsItemRegistry` | **Вырезаем** из Rats Reborn (решение 2026-05-27), см. C7 в `14-план-чинок` |
| Дальнобойные крысы уже есть, но примитивные | `RatRangedAttackGoal` | Стрелы бесконечные, есть мёртвый код `new ItemStack(Items.ARROW)` |
| Зачарование непрозрачное | `EnchanterRatUpgradeItem` | 1000 тиков, случайный уровень, результат может выпасть на землю |
| Крафтовый стол требует крысу ровно сверху | `RatCraftingTableBlockEntity` | Проверка только AABB над блоком |
| Create / Farmer's Delight | поиск по исходникам | Интеграции нет вообще |
| Quarry слабый | `RatQuarryBlockEntity`, `RatQuarryGoal` | Радиус 2, один рабочий сценарий, capability отдаётся одной стороной |
| Ошибки глотаются | `RatDepositGoal`, `RatPickupGoal` | `catch (Exception)` с комментарием `container is empty` |

## Очередность работ

### Этап 0. Подготовка базы

Цель: чтобы любая правка была проверяемой.

1. Поставить Git, JDK 17 и JDK 21.
2. Инициализировать репозиторий в `Rats Reborn`.
3. Зафиксировать чистую базу `Rats-1.20`.
4. Проверить сборку текущей версии 1.20.1.
5. Завести ветку порта 1.21.1.

Выход этапа: проект собирается в исходном виде, есть первая точка отката.

### Этап 1. Порт на 1.21.1

Это первый рабочий этап. Пока мод не собирается и не запускается на Minecraft 1.21.1, остальные механики нельзя нормально тестировать.

Статус первого прохода описан в отдельном файле: [12-статус-порта-1.21.1.md](12-статус-порта-1.21.1.md).

План:

1. Обновить Gradle, NeoForge, Java, mappings и зависимости.
2. Добиться запуска `compileJava` на 1.21.1.
3. Переписать capability-слой под NeoForge 1.21.1:
   - убрать `LazyOptional`;
   - заменить старые `ForgeCapabilities`;
   - зарегистрировать provider через `RegisterCapabilitiesEvent`;
   - обновить работу с инвентарями, жидкостями и энергией.
4. Переписать registry-слой:
   - заменить `ForgeRegistries`;
   - заменить `RegistryObject`;
   - перевести регистрации на `DeferredHolder`, `BuiltInRegistries` и `NeoForgeRegistries`.
5. Починить изменения Minecraft API:
   - меню;
   - рецепты;
   - навигация сущностей;
   - типы мобов;
   - генерация данных.
6. Починить client API:
   - события клиента;
   - отрисовку слоёв;
   - overlay;
   - JEI-интеграцию.
7. Запустить клиент 1.21.1 и проверить, что мод грузится без падения.

Выход этапа: мод собирается на 1.21.1, клиент запускается, можно начинать игровые правки.

### Этап 2. Быстрые исправления, которые сразу убирают боль

#### Приручение за 3-5 кормлений

Файл: `server/entity/ai/goal/WildRatTargetFoodGoal.java`.

План:

1. Вынести настройки в `ServerConfig` и `RatConfig`:
   - минимальное число кормлений;
   - гарантированное число кормлений;
   - доверие за один сыр;
   - порог доверия.
2. По умолчанию поставить 3-5:
   - приручение не раньше 3;
   - гарантированно на 5;
   - шанс после 3 кормлений.
3. Обновить русскую и английскую локализацию.

Правило реализации: без скрытых случайных фоллбеков. Если конфиг задан некорректно, писать явную ошибку и не подменять значение молча.

#### Сохранение стороны контейнера

Файл: `server/entity/rat/TamedRat.java`.

План:

1. В `addAdditionalSaveData` записывать `DepositFacing` и `PickupFacing`.
2. В `readAdditionalSaveData` проверять границы индекса `Direction`.
3. При ошибочном NBT логировать причину.

Это должно убрать часть случаев, когда крыса после перезахода помнит сундук, но не может в него положить предмет.

#### Проверки владельца в пакетах

Файлы:

- `server/message/RatCommandPacket.java`
- `server/message/SyncRatStaffPacket.java`

План:

1. Все команды к приручённой крысе разрешать только владельцу.
2. Для чужого игрока писать предупреждение в лог.
3. Для сервера без владельца явно отклонять действие.

### Этап 4. Радиусы, телепорт и безопасность

#### Понятный радиус

Проблема: `InventoryRat.getRadius()` возвращает сохранённый радиус только при наличии центра. Игрок может думать, что радиус выставлен, но крыса работает от себя.

План:

1. Разделить понятия:
   - радиус поиска;
   - дистанция взаимодействия;
   - радиус дома;
   - дистанция телепорта;
   - максимальная дистанция задания.
2. Показать эти значения в GUI и подсказках предметов.
3. Добавить визуализацию зоны при удержании посоха.

#### Массовый контроллер крыс

Нужен новый предмет: условно **Крысиный зов**.

Функции:

- выбрать группу крыс;
- телепортировать к игроку;
- телепортировать домой;
- посадить всех;
- поставить FOLLOW / SIT / TRANSPORT / HARVEST группе;
- видеть список крыс, статус и последнюю ошибку.

Технически:

- хранить список UUID в предмете;
- проверять владельца каждой крысы;
- уметь находить крысу в загруженных чанках;
- для незагруженных крыс писать понятное сообщение;
- позже добавить сохранённый реестр крыс игрока на уровне мира.

#### Безопасность крыс

План:

1. Улучшить `attemptTeleport`:
   - не телепортировать в жидкость;
   - не телепортировать на опасные блоки;
   - проверять высоту падения;
   - логировать отказ.
2. Добавить антизастревание:
   - если крыса долго не движется и цель не меняется, пересчитать путь;
   - после нескольких провалов сменить маршрут или телепортировать.
3. Добавить запрет глупого падения:
   - проверка следующего узла пути;
   - ограничение падения для приручённых крыс;
   - аварийный телепорт к последней безопасной позиции.

Файлы:

- `TamedRat.java`
- `RatFollowOwnerGoal.java`
- `RatNavigation.java`
- `RatNodeEvaluator.java`
- `RatMoveControl.java`

### Этап 6. Трубы как настоящий проход

Сейчас `RatTubeBlockEntity.updateRat()` содержит закомментированный старый A*, а `RatTubeMoveControl` не ведёт крысу по сети. Это отдельная крупная задача.

План:

1. Создать граф труб:
   - сегмент трубы;
   - соединения по сторонам;
   - открытые входы;
   - клетки как точки входа/выхода.
2. Сделать серверный поиск пути по графу труб.
3. Научить обычный pathfinding учитывать трубу как быстрый участок маршрута:
   - земля до входа;
   - проход по трубе;
   - выход возле цели.
4. Переписать `RatTubeMoveControl`, чтобы он явно двигал крысу от узла к узлу.
5. Подключить трубы к `RatDepositGoal`, `RatPickupGoal`, `RatQuarryGoal`, `RatFollowOwnerGoal`.

Тестовые сценарии:

- прямая труба;
- поворот;
- вертикальная труба;
- труба между клеткой и сундуком;
- труба между карьером и складом;
- несколько крыс в одной сети.

### Этап 13. Голод крыс и кормушка с сыром

**Замысел:** сыр перестаёт быть только ресурсом приручения и крафта — приручённые крысы регулярно едят сыр, иначе не работают (см. этап 19).

**Сейчас в коде:** `TamedRat.isFood()` принимает сыр; постоянного голода нет. Команды с флагом «еда» (`WANDER`, `SIT`, `FOLLOW`, `PATROL`) не требуют кормления для работы.

**Новые объекты:**

| ID (черновик) | Тип | Описание |
|---------------|-----|----------|
| `rat_feeder` | полублок + block entity | Кормушка: инвентарь как у бочки (27 слотов), крыса подходит и «тыкается» в блок для приёма пищи |
| `RatHunger` | данные сущности | Шкала сытости 0–100, расход за тик работы/бега |

**План реализации:**

1. Ввести `EntityDataAccessor` / NBT: `hunger`, `lastFedGameTime`, пороги «голодна» / «сыта».
2. Расход сытости:
   - базовый тик при активной рабочей команде;
   - дополнительный при беге, бое, переносе стака;
   - нулевой или сниженный в `SIT` и внутри домика (этап 14).
3. Блок `RatFeederBlock` (нижняя половина блока, как плита или кастомный `SlabBlock` с BE):
   - GUI как у бочки;
   - приём только предметов из тега `rats:rat_food` (сыр, голубой сыр, нижний сыр — по конфигу);
   - цель ИИ `RatSeekFeederGoal`: найти кормушку с сыром в радиусе дома или радиуса поиска;
   - взаимодействие: крыса в радиусе 1 блока, смотрит на кормушку, забирает 1 сыр за приём пищи, восстанавливает сытость.
4. Связать с посохом: опционально отметить кормушку как «склад корма» для группы крыс.
5. Конфиг `ServerConfig`: скорость голода, минимальная сытость для `HARVEST` / `TRANSPORT` / `GATHER`.
6. Логирование: `LOGGER.warn` при отказе работать из‑за голода с указанием UUID крысы и владельца.

**Файлы-ориентиры:** `TamedRat.java`, `InventoryRat.java`, `WildRatTargetFoodGoal.java`, `RatsBlockRegistry`, новый `RatFeederBlockEntity`.

### Этап 14. Домики крыс и возрождение

**Замысел:** цельный блок-домик с лазанием как у лестницы; привязанная крыса ночью (или по расписанию — этап 15) заходит внутрь; умершая приручённая крыса возрождается у своего домика.

**Сейчас в коде:**

- `InventoryRat.HOME_POS` — точка «дома» через посох (не блок).
- `TamedRat.RespawnCountdown` — после смерти копия с таймером 1200 тиков, без привязки к блоку-дому.
- `RatStayCloseToHomeGoal` — держит крысу рядом с `HOME_POS`.

**Новые объекты:**

| ID (черновик) | Тип | Описание |
|---------------|-----|----------|
| `rat_house` | полный блок | Внешний вид домика; `climbable` как лестница для крыс |
| `rat_house` (BE) | block entity | Владелец, список привязанных UUID крыс (лимит по конфигу), таймер возрождения |

**План реализации:**

1. Привязка: ПКМ владельца с посохом или пустой рукой — записать `GlobalPos` домика в крысу (`BOUND_HOUSE_POS`).
2. Вход: цель `RatEnterHouseGoal` — путь к основанию блока, подъём по грани (кастомный `RatClimbNavigation` или флаг на `RatNavigation` для `climbable`).
3. Внутри: крыса как пассажир BE или невидимая точка отдыха внутри AABB блока (как пчела в улье — ориентир для анимации).
4. Смерть:
   - при `BOUND_HOUSE_POS` и живом домике не дропать улучшения навсегда;
   - запустить `respawnAtHouseTicks` на BE;
   - по окончании — новый `TamedRat` с копией NBT (имя, гены, улучшения, косметика), как сейчас `copy.setRespawnCountdown`, но позиция = центр домика.
5. Если домик сломан — явное сообщение владельцу и запись в лог; крыса использует старый `HOME_POS` или ждёт нового домика (без молчаливого телепорта в ноль).
6. Совместимость: старый `HOME_POS` с посоха остаётся «рабочей точкой днём», домик — «ночное убежище и точка возрождения» (разделение с этапом 15).

**Файлы-ориентиры:** `TamedRat` (смерть, клон), `CheeseStaffScreen`, `ForgeClientEvents` (иконка дома).

### Этап 15. Распорядок дня

**Замысел:** привязать поведение к времени суток: отдых / сон, поход в домик, утром возврат к рабочей точке (`PICKUP_POS`, `DEPOSIT_POS`, карьер, сиденье Create).

**Биология:** дикие крысы в основном **ночные** (активны с сумерками). Для геймплея разумный компромисс:

- **день (6000–12000):** рабочие команды, сбор, перенос, Create-линия;
- **вечер (12000–13000):** переход к дому;
- **ночь (13000–23000):** сон в домике или `SIT` у дома, если домика нет;
- **рассвет (23000–6000):** выход из домика, маршрут к последней рабочей точке.

Вариант в конфиге: `nocturnalRats = true` — инвертировать расписание (работа ночью, сон днём) для «реалистичных» стай.

**План реализации:**

1. Сервис `RatDaySchedule` (уровень мира): фаза суток, проверка `level.getDayTime() % 24000`.
2. Цели с высоким приоритетом в фазе отдыха:
   - `RatReturnToHouseGoal`;
   - `RatSleepInHouseGoal` (флаг `SLEEPING` из `AbstractRat` уже есть).
3. При смене на «работа»:
   - восстановить сохранённую `WORK_ANCHOR` (`GlobalPos`: склад, карьер, сиденье);
   - не сбрасывать команду игрока, только приостанавливать исполнение.
4. GUI крысы: строка «фаза: работа / отдых / голод / нет пути».
5. **Create Aeronautics (критично):** до включения расписания на кораблях/платформах:
   - аудит `RatNavigation`, `RatMoveControl`, `RatFollowOwnerGoal`;
   - тест: крыса на движущемся contraption, крыса на швартовке, крыса при разборке корабля;
   - при потере опоры — `attemptTeleport` к `WORK_ANCHOR` или домику с записью причины в лог;
   - документировать ограничения в `12-статус-порта-1.21.1.md` после smoke-теста с Create + Aeronautics.

**Зависимости:** этапы 13–14, стабильный pathfinding (этап 4), Aeronautics (этап 12).

### Этап 16. Крысы-медики и борьба с чумой

**Замысел:** приручённая крыса-медик ищет заражённых чумой крыс в радиусе и лечит уколом (шприц).

**Сейчас в коде:** чума у диких (`Rat.PLAGUE`), эффект `PlagueMobEffect`, `PurifyingLiquid`, улучшения лечения у игрока нет для крыс.

**Новые объекты:**

| ID (черновик) | Тип | Описание |
|---------------|-----|----------|
| `rat_upgrade_medic` | улучшение | Включает цели медика |
| `rat_syringe` | предмет в лапах (визуал) | Опционально расходник или чисто косметика |
| `RatCurePlagueGoal` | цель ИИ | Сканирование `RatsEntityTypeTags.RATS` + флаг чумы / эффект |

**План реализации:**

1. Скан: каждые N тиков `level.getEntitiesOfClass` в радиусе R (конфиг, по умолчанию 16 блоков).
2. Приоритет: ближайшая заражённая дикая крыса → союзная приручённая с чумой (если возможно).
3. Подход, анимация укола, снятие `PLAGUE` / эффекта `PLAGUE`, кулдаун на цель.
4. Расход: 1 сыр или 1 зелье из инвентаря крысы/кормушки (конфиг) — без бесконечного лечения.
5. Шапка «медицинский колпак» (этап 11) — только визуал.

### Этап 17. Крысы-работяги Create (конвейерная линия)

**Замысел:** улучшение с ключом Create; крыса сидит на сиденье у конвейера, берёт предмет из сундука в радиусе 1 блока и применяет его к предмету на ленте — замена автономного активатора в цепочке только из крыс.

**Сейчас в коде:** этап 7 плана — ручка/рычаг (`rat_upgrade_operator`); интеграции с Belt нет.

**Новые объекты:**

| ID (черновик) | Тип | Описание |
|---------------|-----|----------|
| `rat_upgrade_conveyor_worker` | улучшение | Требует ключ Create в крафте |
| `RatConveyorWorkGoal` | цель ИИ | Работа у привязанного рабочего места |

**Геометрия рабочего места (жёстко, без «примерно»):**

```
[сундук] — 1 блок — [сиденье + крыса] — вплотную — [лента Create]
```

- Сундук (или совместимый контейнер): Manhattan-дистанция ≤ 1 от сиденья.
- Сиденье Create: крыса **прилеплена** как пассажир (`startRiding` / anchor), слезает только по команде, голоду или смене фазы суток.
- Лента: соседний блок к сиденью; предмет на ленте в зоне досягаемости крысы (1 блок вперёд по направлению ленты).

**План реализации:**

1. Привязка: ПКМ посохом по сиденью → `WORK_SEAT_POS` + направление ленты.
2. Слой `compat/create`: доступ к `TransportedItemStack` / Belt API (только при загруженном Create).
3. Цикл: взять 1 предмет из сундука → дождаться предмета на ленте → `ItemInteraction` (обработка как Deployer: резать, молоть, крафтить — по тегу инструмента в сундуке).
4. Выход: положить результат на ленту или в второй сундук (настройка).
5. Ошибки в лог: нет сундука, пустая лента, несовместимые предметы, Create не установлен (улучшение не активируется, предмет в руке с подсказкой).
6. Не конфликтовать с `rat_upgrade_crafting` и operator: таблица конфликтов в `RatsUpgradeConflictRegistry`.

### Этап 19. Голодный грабёж (приручённые воруют)

**Замысел:** дикие крысы уже грабят сундуки (`RatRaidChestsGoal` у `DiggingRat`). При **нехватке сыра** в кормушке даже приручённые прекращают работу и ищут еду в контейнерах поблизости.

**Сейчас в коде:**

- `rat_upgrade_pickpocket` — воровство у **мобов**, не у сундуков.
- `DiggingRat` + `RatRaidChestsGoal` — только дикие, конфиг `ratsStealItems`.
- Тег `rats:unraidable_containers` — защищённые контейнеры.

**План реализации:**

1. При `hunger < hungerRaidThreshold` и пустой привязанной кормушке:
   - снять рабочие цели (`HARVEST`, `TRANSPORT`, …);
   - включить `RatStarvingRaidGoal` (форк логики `RatRaidChestsGoal` для `TamedRat`).
2. Уважать `unraidable_containers` и владельца: не воровать из сундуков с замком другого игрока на сервере; whitelist «своих» сундуков опционально.
3. После поедания найденного сыра — вернуть прежнюю команду и `WORK_ANCHOR`.
4. Сообщение владельцу: «Крыса X голодна и грабит сундуки» (action bar или журнал).
5. Конфиг: `tamedRatsRaidWhenStarving`, порог голода, радиус поиска.

**Связь:** этап 13 (кормушка), этап 3 (единое рабочее состояние с причиной остановки).

## Критерий готовности механики

Каждая новая механика считается готовой только если:

- есть явная документация в `документация/`;
- есть понятная ошибка в логе при невозможной операции;
- нет скрытых фоллбеков;
- GUI или подсказка объясняют игроку условия работы;
- сохранение и перезаход не ломают состояние;
- механика проверена в одиночной игре и на сервере.
