# Кодировки текстовых файлов

## Цель

Все текстовые файлы проекта должны храниться в UTF-8 без BOM. UTF-16 ломает загрузку ресурсов Minecraft: модели, состояния блоков, таблицы добычи и рецепты начинают читаться как битый JSON, после чего игра показывает чёрно-фиолетовый куб или пишет ошибку разбора данных.

## Защита в проекте

В `Rats-1.20/build.gradle` добавлена задача `normalizeTextEncoding`.

Она запускается автоматически перед:

- `compileJava`
- `processResources`

Задача проверяет исходники, ресурсы, сгенерированные ресурсы и документацию. Если файл с расширением `java`, `json`, `mcmeta`, `toml`, `cfg`, `properties`, `txt`, `md`, `gradle`, `yml` или `yaml` сохранён как UTF-16 либо UTF-8 с BOM, файл сразу перезаписывается в UTF-8 без BOM.

Если после нормализации в текстовом файле остаются нулевые байты, сборка падает с явной ошибкой и путём к проблемному файлу.

## Ручной запуск

```powershell
Set-Location "c:\Users\user\Desktop\Rats Reborn\Rats-1.20"
.\gradlew.bat normalizeTextEncoding --no-daemon
```

## Правила редактора и Git

Добавлены файлы:

- `.editorconfig` в корне рабочего каталога
- `.gitattributes` в корне рабочего каталога
- `Rats-1.20/.editorconfig`
- `Rats-1.20/.gitattributes`

Они требуют UTF-8 и перевод строки LF для текстовых файлов. Двоичные файлы (`png`, `jar`) помечены как двоичные.

## Что делать после правки ресурсов

1. Запустить обычную сборку.
2. Убедиться, что в выводе есть строка `UTF-8 normalization completed`.
3. Если менялся мод, заменить jar в клиенте.
4. При проблеме с моделью или JSON смотреть `latest.log`: теперь ошибка должна быть содержательной, а не из-за UTF-16.
